# 문서 규약

이 문서를 수정하거나 새 엔드포인트를 추가할 때 따르는 규약입니다.

***

## 상태 표기

확인 수준을 표기합니다. 추정과 확인된 사실이 섞이지 않도록 하는 장치이므로, 새 항목을 추가할 때도 반드시 하나를 붙입니다.

| 표기 | 의미 |
|---|---|
| 실측 | 경로, 파라미터, 응답을 모두 확인 |
| 스키마 미상 | 경로와 인증은 확정. 응답 스키마는 빈 배열이나 `null` 로만 관측 |
| 경로만 확인 | 파라미터 미검증 |
| 추정 | 실측 근거 없음 |
| 조회용 POST | 메서드는 `POST` 이나 서버 상태를 변경하지 않음 |

인증이 필요한 API에는 인증 필요, 민감 정보를 포함하는 응답에는 민감 정보 포함을 함께 적습니다.

***

## 작성 규칙

엔드포인트는 정본 한 곳에만 상세히 쓰고 나머지 문서에서는 링크로 참조합니다.
같은 내용을 여러 곳에 쓰면 한쪽만 수정되면서 문서 간에 값이 어긋납니다.

링크는 상대경로로 씁니다. `§6.4` 같은 절 번호 참조는 문서를 재편할 때마다 깨지므로 사용하지 않습니다.

제목 맨 앞에는 이모지를 두지 않습니다. 일부 마크다운 렌더러가 앵커를 `#-제목` 형태로 만들어 다른 문서에서 건 링크가 깨집니다.

실측 근거가 없는 내용은 추정임을 밝히고 그 근거를 함께 적습니다.
이 문서는 잘못 알려진 통념을 실측으로 바로잡는 것을 목적으로 합니다.

새 엔드포인트를 추가하면 [엔드포인트 전체 목록](reference/endpoints.md)도 함께 갱신합니다.
이 표는 손으로 관리하며, 이 저장소에서 엔드포인트를 찾는 경로는 이 색인 하나뿐입니다.
헤더의 건수 집계도 함께 수정합니다.

***

## 문서 어투

치지직 [공식 개발자 문서](https://chzzk.gitbook.io/chzzk)의 서술 방식을 따릅니다.

- 각 API는 `~을 조회할 수 있습니다` 형태의 한 문장으로 시작합니다.
- 동작을 설명할 때는 `~합니다`, `~됩니다` 를 씁니다. 독자에게 지시하는 문장은 쓰지 않습니다.
- 강조를 위한 이모지나 굵은 글씨를 남용하지 않습니다. 사실을 그대로 서술합니다.
- 표는 `HTTP Request`, `Request Param`, `Response Body` 순으로 배치합니다.
- `required` 칸에는 필수면 `*`, 선택이면 `optional` 을 적습니다.
- 중첩 필드는 들여쓰기 대신 전체 경로로 적습니다. 예: `card.content.extraLinks`

한 문단 안에서 문장을 줄로 나눌 때는 줄 끝에 백슬래시를 붙입니다.

## 캡처 자료를 다룰 때

크롬의 sanitized HAR 내보내기는 쿠키와 요청 헤더만 제거하며 응답 본문은 지우지 않습니다.
`streamKey`, `accTkn`, `liveTokenList` 같은 값은 모두 응답 본문에 있으므로, HAR을 공유하거나 커밋하기 전에 응답 본문까지 제거하는 별도 스크럽이 필요합니다.

댓글과 채팅 응답에는 다른 이용자의 닉네임과 `userIdHash` 가 포함됩니다. 예시로 옮길 때는 치환합니다.

실제 값을 예시에서 발견하면 플레이스홀더로 치환합니다.

***

## 사이트 생성

문서를 수정한 뒤에는 사이트를 다시 생성합니다.

```bash
python book/build.py
python book/check-links.py
```

`book/site.html` 은 생성물이므로 직접 수정하지 않습니다. 내용은 `docs/` 의 `.md` 를, 겉모습은 `book/template.html` 을 수정합니다.
`docs/SUMMARY.md` 도 생성물입니다. 목차는 디렉터리 구조에서 만들어지므로 손으로 고치지 않습니다.
